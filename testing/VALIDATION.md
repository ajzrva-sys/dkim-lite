# Release validation record

## v0.1.0 qualification

Qualification completed on 2026-07-31 in clean FIPS-enabled Rocky Linux
guests. These are RHEL-compatible Rocky builds, not tests performed on Red Hat
subscription images.

| Target | Guest | System crypto | RPM `%check` | Runtime linkage | Packaged service |
| --- | --- | --- | --- | --- | --- |
| el8 | Rocky Linux 8.10 | FIPS enabled | Pass | system OpenSSL 1.1.1 and glibc | active |
| el9 | Rocky Linux 9.8 | FIPS enabled | Pass | system OpenSSL 3 and glibc | active |
| el10 | Rocky Linux 10.1 | kernel FIPS enabled | Pass | system OpenSSL 3 and glibc | active |

Each final RPM was built with `cargo build --release --locked --offline` from
the same deterministic source archive. Each `%check` run completed 18 unit
tests, the daemon integration test, and documentation tests with zero failures.
`rpm -K` reported valid digests for every binary RPM and SRPM.

The installed systemd unit on all three guests had SHA-256
`efa3cb832b384e85bc6fce97ed642b93fdc0573fdb9f6a782263c3f3d3bdbd2d`,
identical to the corrected unit in the qualified source. `systemd-analyze verify`
accepted the unit. The installed daemon started successfully with
`require_fips=true` on all three guests.

The SELinux policy includes both `/run/dkim-lite(/.*)?` and its `/var/run`
alias because the file-context matcher differs across release families. After
install and service restart, the runtime directory and socket resolved to
`dkim_lite_var_run_t` on all three systems with SELinux enforcing.

Postfix signing was exercised through loopback TCP and Unix-domain milter
sockets during platform qualification. The Rocky 9 packaged Unix-socket message
was accepted independently by OpenDKIM (2048-bit verification success) and
Rspamd (`R_DKIM_ALLOW`); the same independent verification path was previously
exercised on Rocky 10. No AVC denial was generated by the Unix-socket tests.
